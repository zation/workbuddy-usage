# 分组口径归一化 Spec

## 背景与目标

分组维度取值是 `sessions.cwd`（v1 R5）。实测外部 `sessions` 表的 `group_id`、`group_title`、`project_id` **全部为 NULL**，不存在分组类型字段；`conversation_origin` 与 `is_playground` 与自动目录只是相关，不能作为判据（74 个日期目录会话中 68 个 `is_playground = 1`、6 个为 0）。派生库 80 个分组里有 71 个是 WorkBuddy 按时间戳自动生成的日期目录，形如 `/Users/liuyang/WorkBuddy/2026-10-17-21-46-27`，在筛选下拉里形成大量无意义条目，也把按分组拆分切得过碎。上述计数为本地派生库的一次历史快照，与 `integration.md` 的实测快照日期不同，仅说明量级，不作断言。

本交付用**路径形态**识别自动分组，把它们收敛为一个「默认」分组：筛选下拉不再出现日期条目，统计时统一计入「默认」，手动分组保持原样。原始 `group_path` 不改写，分组归属口径不变。

## 与初始需求的关系

本 Spec 的需求**直接覆盖** v1.0.0 `usage-stats-spec.md` 中 R5 的分组展示与聚合方式（业务键仍取 `sessions.cwd`，不改变归属），以及 `product-brief.md` 关键术语「分组」、`data-model.md` 的 C7 / C11 分组快照说明、`integration.md` 的关联键与兼容性风险表。归档的 v1.0.0 三份文档不改写；长期文档按本 Spec 更新：`product-brief.md`、`technical-architecture.md`（接口表 `group` 参数的虚拟键说明）、`data-model.md`（`groups` 表结构与新增约束）、`integration.md`（字段全 NULL 的实测事实、路径判据与兼容性风险）。

`usage-panel-polish` 与 `model-color-binding` 均已实施完毕，本交付在其之上修改 `server/query.ts`（`getBreakdown` / `buildWhere` / `getRequests`）与 `FilterBar.tsx`。增补的下拉统一会把 `FilterBar` 的三个原生 `select` 与自定义模型下拉换成同一份组件，属面板控件改造，不改服务层口径；分组筛选下拉的选项仍完全由服务层聚合结果驱动。分组口径需独立验收维度一致性。

## 范围与非目标

**范围**

- 在解析层按 `cwd` 路径形态判定自动分组，结果落 `groups.is_auto`。
- `groups` 维表加列，`SCHEMA_VERSION` 递增触发派生库重建。
- 服务层把自动分组聚合为「默认」：按分组拆分、分组筛选下拉、请求明细的分组展示。
- 支持 `group=默认` 作为虚拟业务键筛选全部自动分组。
- 判定规则兼容 macOS 的 POSIX 路径与 Windows 的盘符 / 反斜杠路径。
- 同步长期文档与测试。

**非目标**

- 不改变分组归属口径：仍取 `sessions.cwd`，不按 jsonl 目录名反解，不使用 `sessions.group_id` / `group_title` / `project_id`。
- 不改写或删除 `groups.group_path`，不改写 `requests.group_id`；派生库仍保留每个原始路径一行。
- 不把「未知分组」（`cwd` 为空或维表缺失）并入「默认」。
- 不对展示名撞「默认」的手动分组做去重、回退或改名。
- 不提供分组类型开关、手动打标、分组重命名或自动分组的排除开关；筛选条件仍只有时间、分组、对话、模型四项。
- 不改面板的 tab、数值单位、明细折叠等交互（属另一交付）。
- 不处理子代理积分（见 `docs/backlog/subagent-credit-reconciliation.md`）。
- 不改 `~/.workbuddy` 下任何原始数据，不新增外部数据源。

## 用户或系统行为

1. 分组筛选下拉不再出现日期形态条目，只列出当前筛选范围内**实际存在**的手动分组、自动分组聚合项「默认」以及「未知分组」；三者都遵循「有数据才出现」，「默认」在该范围内没有自动分组请求时不占位。
2. 按分组拆分列表把所有自动分组聚合为一行「默认」，其数值为这些请求按现有口径重新聚合的结果，占比按全量合计计算。
3. 点击「默认」即把分组筛选设为该虚拟业务键，所有视图只显示自动分组的请求；点击手动分组行为不变。
4. 请求明细表的分组列对自动分组显示「默认」；该列的 hover 提示仍是原始 `group_path`（日期路径），属已知且接受的行为。
5. 「默认」与其它分组遵循同一套筛选语义：当前值由下拉框表达，清除通过「全部分组」或「重置」。
6. 派生库结构版本不匹配时按现有机制删库全量重建，重建后分组结果一致。

## 业务规则

**R1 自动分组判定**
对 `cwd` 统一按 `/` 与 `\` 切分并去掉尾部空段，取末段与倒数第二段：末段匹配 `^\d{4}-\d{2}-\d{2}-\d{2}-\d{2}-\d{2}$`，且倒数第二段等于 `workbuddy`（大小写不敏感）时判为自动分组。`is_auto = 1` 表示该 `cwd` 是 WorkBuddy 按时间戳自动创建的工作目录，**不依据** `is_playground` / `conversation_origin` 等会话字段判定。规则不依赖运行平台的分隔符，不硬编码用户名、盘符或 home 目录，兼容 `/Users/<user>/WorkBuddy/<日期>` 与 `C:\Users\<user>\WorkBuddy\<日期>`。末段是日期但父目录不是 `WorkBuddy` 的路径，以及 `WorkBuddy` 目录下的非日期目录，均判为手动分组。空串与取不到 `cwd` 时归入「未知分组」，不参与本规则。

**R2 判定只做一次**
判定在解析层 `ensureGroup` 插入维表行时完成，结果存 `groups.is_auto`；服务层与面板不重复实现路径规则。`is_auto` 是 `group_path` 的纯函数派生值，而 `group_path` 带 UNIQUE 约束，因此同一业务键的判定结果恒定，维表行按既有 `ON CONFLICT DO NOTHING` 语义保持快照（C7 / C11），增量刷新不改写已有行。判定规则变更属于派生规则变更，必须递增 `SCHEMA_VERSION` 触发删库重建，不依赖增量刷新纠正存量行。外部会话被清理后保留原行。

**R3 表结构与版本**
`groups` 增加 `is_auto INTEGER NOT NULL DEFAULT 0`；`SCHEMA_VERSION` 由当前的 2 递增 1 为 3（实施时以当时的当前版本为准，只递增 1），启动时版本不匹配即删库重建（沿用现有机制，不写迁移脚本）。重建后内部 `id` 重新分配，API 仍一律使用业务键字符串（C14）。

**R4 按分组聚合**
`getBreakdown` 的 group 维度，`key` 与 `name` 对自动分组统一取常量「默认」，其余保持 `group_path` / `display_name`；`GROUP BY` 改用与 `key` 相同的表达式，使全部自动分组合成一行。`COUNT(DISTINCT r.session_id)`、`tokenShare` / `creditShare` 的计算方式不变，合并后的「默认」行是这些请求**按现有 SQL 重新聚合**的结果（会话数为跨自动分组的去重值，不是各分组之和）。维表缺失行仍兜底为「未知分组」（C13）。手动分组的展示名恰为「默认」时**不做任何特殊处理**：`key` 仍是完整路径、`name` 仍是「默认」，下拉可出现两个同名项，因业务键不同，筛选互不影响。

**R5 虚拟业务键**
`buildWhere` 中 `group = '默认'` 映射为 `g.is_auto = 1`，其它取值仍映射为 `g.group_path = ?`。「默认」是虚拟键，不与任何业务键相等：`group_path` 是完整 `cwd` 路径，或保留字「未知分组」，两者都不等于「默认」。服务层 `readFilters` 对 `group` 只做 `trim()`、无白名单校验，虚拟键可原样透传。维度筛选值仍由服务层按当前筛选范围聚合得出，自动分组不再单独枚举。

**R6 明细展示**
`getRequests` 返回的 `groupName` 对自动分组显示「默认」；`group` 字段仍为原始 `group_path` 业务键，不随展示名改变。面板不因该字段变化新增交互；明细分组列的 `title` 仍取 `group`，因此 hover 会显示日期路径，属已知行为。

**R7 未知分组独立**
「未知分组」保持独立一行，不并入「默认」；其成因（`cwd` 为空、外部会话被清理后重解析）与现有 C7 / C13 处理不变。

**R8 一致性**
自动分组归并只改变分组的展示粒度，不改变任何请求行与聚合口径：在「全部时间 + 无筛选」下，按分组拆分各项指标之和仍等于总览合计（v1 R13 / AC3）；分组、对话、模型三种维度各自的求和仍一致。

**R9 只读与边界**
外部 `sessions.cwd` 仍以只读方式读取，不写 `workbuddy.db`；判定规则不引入网络调用或新的外部数据源。

## 边界情况

| 情况 | 处理 |
| --- | --- |
| Windows 路径含盘符、反斜杠、末尾反斜杠 | 统一切分后按 R1 判定，大小写不敏感 |
| `WorkBuddy` 目录名大小写不同（Windows） | 倒数第二段比较忽略大小写 |
| 路径末段形似日期但父目录不是 `WorkBuddy` | 判为手动分组，保留原展示名 |
| `WorkBuddy` 目录下用户手动创建的非日期目录 | 判为手动分组，保留原展示名 |
| `cwd` 为空串、NULL 或维表行缺失 | 归入「未知分组」，`is_auto = 0`，不并入「默认」 |
| 手动分组路径末段恰为「默认」 | 不去重、不回退、不改名：业务键仍是完整路径、展示名仍是「默认」；下拉出现两个同名「默认」项，筛选互不影响 |
| 当前筛选范围内没有自动分组请求 | 下拉不出现「默认」；若当前筛选值仍为「默认」则由兜底项补上，不占位 |
| 旧链接 / 遗留状态携带日期路径业务键 | `buildWhere` 仍按 `g.group_path = ?` 精确匹配，不报错；下拉兜底项可能短暂显示该日期路径，刷新页面后消失 |
| 请求明细分组列 hover | 单元格文本显示「默认」，hover 提示仍为原始 `group_path`；属已知且接受的行为 |
| 外部会话被清理 | 维表行与 `is_auto` 快照保留；文件重新解析且会话已不存在时按 C7 指向「未知分组」 |
| WorkBuddy 以后改变自动目录命名格式 | R1 判定失效，新目录被当作手动分组；必须更新规则并递增 `SCHEMA_VERSION` 重建索引，不静默猜测，也不依赖增量刷新纠正存量行 |
| `group` 参数传入「默认」但库中没有自动分组 | 返回空结果，不报错 |
| 结构版本不匹配 | 按现有机制删库重建，重建后 `is_auto` 与聚合结果一致 |
| 删库重建后 | 内部 `id` 重新分配，API 参数与返回值仍只用业务键（C14） |

## 验收标准

- **AC1 判定规则**：单测覆盖 macOS POSIX 路径、Windows 盘符 / 反斜杠路径、末尾分隔符、大小写差异、日期末段但父目录不同的路径、`WorkBuddy` 目录下的非日期目录、空 `cwd`，结果与 R1 一致。
- **AC2 筛选下拉**：分组下拉由服务层聚合结果驱动的选项不再出现任何 `YYYY-MM-DD-HH-MM-SS` 形态条目，只保留实际存在的手动分组、「默认」与「未知分组」；「默认」与手动分组一样仅在有对应请求时出现，库中无自动分组时不占位。断言不含「当前值兜底项」：旧链接 / 遗留状态携带日期路径业务键时兜底项可能短暂显示该路径，属边界表已记录的已知行为，刷新页面后消失。
- **AC3 拆分聚合**：按分组拆分列表中「默认」为一行的数值，等于全部自动分组请求按现有口径重新聚合的结果；手动分组的行数与数值与改动前一致；会话数按去重口径验证，不按各分组相加。
- **AC4 虚拟键筛选**：把分组筛选设为「默认」后，总览、趋势、三个拆分列表与请求明细**各自返回的数据**都只含自动分组的请求；清除筛选后恢复全量。
- **AC5 明细展示**：自动分组请求的明细行分组列显示「默认」，`group` 业务键仍为原始路径；hover 提示仍为原始路径，属已知行为。
- **AC6 一致性**：在「全部时间 + 无筛选」下，按分组、按对话、按模型三种拆分各自的指标求和仍等于总览合计（v1 AC3）。
- **AC7 未知分组**：`cwd` 为空的请求仍单独计入「未知分组」，不被并入「默认」。
- **AC8 结构重建**：`SCHEMA_VERSION` 递增后旧派生库自动删库重建；连续两次全量重建的 `groups` 行集合与 group 维度聚合结果一致，与文件遍历顺序无关。
- **AC9 只读边界**：`workbuddy.db` 仍以只读打开，刷新前后外部文件大小与 mtime 不因本项目变化；页面不产生外部域名请求。既有只读单测覆盖连接写入被拒，文件指纹与网络边界由验收脚本 / 人工实测记录。
- **AC10 回归与检查**：v1.0.0 的 AC1–AC10 全部继续通过；其中涉及分组业务键与展示的断言（`tests/acceptance.test.ts` 里按分组业务键硬编码映射的断言、面板分组下拉与拆分列表的展示断言）如因展示口径变化需要调整，须在收尾记录中逐条列明调整前后对照，不得直接删除或跳过；`npm run typecheck`、`npm test`、`npm run build` 通过。
- **AC11 文档同步**：`product-brief.md`、`technical-architecture.md`、`data-model.md`、`integration.md` 中分组相关描述与本 Spec 一致；`integration.md` 明确记录 `group_id` / `group_title` / `project_id` 全为 NULL 的实测事实，以及路径判据与目录格式变化风险。

## 增补需求（2026-11-13 确认）

本交付合并两项面板小优化，与分组口径归一化同批实施、同批验收。它们不改变聚合口径，只改控件与提示。

**范围增补**

- 把时间预设、分组、对话三个原生 `select` 统一为与模型下拉相同的自定义下拉组件，四个下拉共用一份实现与交互。
- 趋势图 tooltip 不再列出数值为 0 的模型系列；Token 与积分两张图遵循同一规则。

**非目标增补**

- 不改日期输入框（仍是原生 `input[type="date"]`），不新增下拉搜索、多选或分组折叠。
- 不改 tooltip 的单位、小数位与数值格式，不改 `series.data` 的按天补 0、堆叠方式与合计口径。
- 不引入第三方 UI / headless 组件依赖。

**行为增补**

7. 四个筛选下拉外观与交互一致：点击展开、↑↓ 移动、Enter 选中、Esc 关闭、点击外部关闭；时间预设保持紧凑宽度，选中「自定义」仍出现日期输入框。
8. 趋势图 hover 时不列出数值为 0 的模型；某天全部为 0 时只显示日期与「无数据」。
9. 两张趋势图遵循同一提示规则。

**R10 下拉组件统一**
`FilterBar` 的四个下拉共用同一个 `Select` 组件（button + `role="listbox"` / `role="option"`），由 props 提供选项、当前值、空值文案与可选的引导图标：模型维度通过渲染回调提供 `ModelDot`，其它维度不显示图标。组件不感知「默认」等业务口径，选项一律来自服务层聚合结果。键盘行为、`aria-expanded` / `aria-controls` / `aria-activedescendant` / `aria-selected`、点击外部关闭与「当前值不在选项中」的兜底项，与现有模型下拉保持一致（↑↓ / Enter / Space / Esc / 点击外部关闭，不新增 Tab 行为）。

**R11 提示过滤 0 值**
趋势图 tooltip 在 `trigger: 'axis'` 下过滤数值 ≤ 0 的系列；保留项按数值降序，首行为日期，每行为系列色点、展示名与格式化数值。没有保留项时只显示日期与「无数据」，不显示 0。日期必须从过滤前的 `params` 取，避免全 0 日丢失日期。过滤只作用于提示内容，`series.data` 仍按天补 0，堆叠、坐标轴与合计口径不变。

**R12 增补部分的边界**
提示过滤不改变面板既有的 0 值模型隐藏规则（`visibleModelKeys`）与任何聚合结果；下拉统一不改变筛选值语义：空字符串表示「全部」，分组「默认」仍是虚拟业务键，清除筛选仍通过「全部分组」或「重置」。

**AC12 下拉一致性**
四个下拉都由同一组件渲染：键盘交互（↑↓ 移动、Enter 选中、Esc 关闭、点击外部关闭）在一个代表性下拉上断言，四个触发按钮的 `role` 与 `aria-expanded` / `aria-controls` / `aria-activedescendant` / `aria-selected` 组合全量检查；时间预设宽度与「自定义」日期输入行为不变，分组 / 对话 / 模型的空值文案分别为「全部分组 / 全部对话 / 全部模型」。

**AC13 提示过滤**
分别在 Token 与积分两张图上 hover，tooltip 不含数值为 0 的模型；全 0 日只显示日期与「无数据」；两张图一致；图表数据、堆叠与合计不变。

**AC14 增补回归**
改造后 `npm run acceptance` 既有 10 项仍全部 PASS，且脚本必须实际运行；脚本按新 DOM 适配，但不放宽任何阈值。运行前提不满足时该项记为「未验证风险」并说明原因，不得记为通过。

## 已确认决策

- 原始数据没有分组类型字段，只能靠路径形态判定；`is_auto` 表示按时间戳自动创建的工作目录，接受该启发式规则并把失效风险写入兼容性风险表。
- 「默认」作为可见的筛选项出现，替代 71 个日期条目；用户未要求隐藏全部自动分组，因此不提供排除开关。
- 「默认」与手动分组、「未知分组」一样，仅在有对应请求时出现，不在下拉里恒定占位。
- 「未知分组」保持独立，不并入「默认」。
- 保留每个原始 `group_path` 一行，只在维表加标记、在服务层聚合，不改写事实表外键。
- 虚拟业务键直接取「默认」；`group_path` 是完整 `cwd` 路径或保留字「未知分组」，均不等于「默认」。
- 手动分组展示名撞「默认」时不做去重或回退，允许下拉出现两个同名项，业务键不同、筛选互不影响。
- `is_auto` 在插入时确定后保持不变，维表沿用 `ON CONFLICT DO NOTHING`；判定规则变更靠 `SCHEMA_VERSION` 递增重建。
- 判定规则集中在解析层，兼容 macOS 与 Windows，不硬编码用户目录。
