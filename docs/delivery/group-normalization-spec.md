# 分组口径归一化 Spec

## 背景与目标

分组维度取值是 `sessions.cwd`（v1 R5）。实测外部 `sessions` 表 254 行的 `group_id`、`group_title`、`project_id` **全部为 NULL**，不存在分组类型字段；`conversation_origin` 与 `is_playground` 与自动目录只是相关，不能作为判据（74 个日期目录会话中 68 个 `is_playground = 1`、6 个为 0）。派生库 80 个分组里有 71 个是 WorkBuddy 自动生成的日期目录，形如 `/Users/liuyang/WorkBuddy/2026-10-17-21-46-27`，在筛选下拉里形成大量无意义条目，也把按分组拆分切得过碎。

本交付用**路径形态**识别自动分组，把它们收敛为一个「默认」分组：筛选下拉不再出现日期条目，统计时统一计入「默认」，手动分组保持原样。原始 `group_path` 不改写，分组归属口径不变。

## 与初始需求的关系

本 Spec 的需求**直接覆盖** v1.0.0 `usage-stats-spec.md` 中 R5 的分组展示与聚合方式（业务键仍取 `sessions.cwd`，不改变归属），以及 `product-brief.md` 关键术语「分组」、`data-model.md` 的 C7 / C11 分组快照说明、`integration.md` 的关联键与兼容性风险表。归档的 v1.0.0 三份文档不改写；长期文档按本 Spec 更新：`product-brief.md`、`technical-architecture.md`（接口表 `group` 参数的虚拟键说明）、`data-model.md`（`groups` 表结构与新增约束）、`integration.md`（字段全 NULL 的实测事实、路径判据与兼容性风险）。

本交付与 `usage-panel-polish-spec.md` 都会修改 `server/query.ts`（本交付改 `getBreakdown` / `buildWhere` / `getRequests`，面板交付改 `getSummary`），按面板可读性优化 → 分组口径归一化的顺序实施，避免同文件冲突。分组筛选下拉的变化由服务层聚合结果驱动，`FilterBar.tsx` 只由面板交付修改；分组口径需独立验收维度一致性。

## 范围与非目标

**范围**

- 在解析层按 `cwd` 路径形态判定自动分组，结果落 `groups.is_auto`。
- `groups` 维表加列，`SCHEMA_VERSION` 递增触发派生库重建。
- 服务层把自动分组聚合为「默认」：按分组拆分、分组筛选下拉、请求明细的分组展示。
- 支持 `group=默认` 作为虚拟业务键筛选全部自动分组。
- 判定规则兼容 macOS 的 POSIX 路径与 Windows 的盘符 / 反斜杠路径。
- 同步长期文档与测试。

**非目标**

- 不改变分组归属口径：仍取 `sessions.cwd`，不按 jsonl 目录名反解，不使用 `sessions.group_id` / `group_title` / `project_id`。
- 不改写或删除 `groups.group_path`，不改写 `requests.group_id`；派生库仍保留每个原始路径一行。
- 不把「未知分组」（`cwd` 为空或维表缺失）并入「默认」。
- 不提供分组类型开关、手动打标、分组重命名或自动分组的排除开关；筛选条件仍只有时间、分组、对话、模型四项。
- 不改面板的 tab、数值单位、明细折叠等交互（属另一交付）。
- 不处理子代理积分（见 `docs/backlog/subagent-credit-reconciliation.md`）。
- 不改 `~/.workbuddy` 下任何原始数据，不新增外部数据源。

## 用户或系统行为

1. 分组筛选下拉不再出现日期形态条目，只列出手动分组、「默认」以及实际存在的「未知分组」。
2. 按分组拆分列表把所有自动分组聚合为一行「默认」，其数值为这些分组之和，占比按全量合计计算。
3. 点击「默认」即把分组筛选设为该虚拟业务键，所有视图只显示自动分组的请求；点击手动分组行为不变。
4. 请求明细表的分组列对自动分组显示「默认」。
5. 「默认」与其它分组遵循同一套筛选语义：当前值由下拉框表达，清除通过「全部分组」或「重置」。
6. 派生库结构版本不匹配时按现有机制删库全量重建，重建后分组结果一致。

## 业务规则

**R1 自动分组判定**
对 `cwd` 统一按 `/` 与 `\` 切分并去掉尾部空段，取末段与倒数第二段：末段匹配 `^\d{4}-\d{2}-\d{2}-\d{2}-\d{2}-\d{2}$`，且倒数第二段等于 `workbuddy`（大小写不敏感）时判为自动分组。规则不依赖运行平台的分隔符，不硬编码用户名、盘符或 home 目录，兼容 `/Users/<user>/WorkBuddy/<日期>` 与 `C:\Users\<user>\WorkBuddy\<日期>`。末段是日期但父目录不是 `WorkBuddy` 的路径，以及 `WorkBuddy` 目录下的非日期目录，均判为手动分组。空串与取不到 `cwd` 时归入「未知分组」，不参与本规则。

**R2 判定只做一次**
判定在解析层 `ensureGroup` 写入维表时完成，结果存 `groups.is_auto`；服务层与面板不重复实现路径规则。维表仍是快照（C7 / C11）：外部会话被清理后保留原行。已存在的分组行在每次刷新时按当前 `cwd` 更新 `is_auto`，`display_name` 与 `group_path` 不变，保证增量刷新后判定与当前外部数据一致。

**R3 表结构与版本**
`groups` 增加 `is_auto INTEGER NOT NULL DEFAULT 0`；`SCHEMA_VERSION` 在当时的当前版本基础上递增 1（本交付排在面板可读性优化之后实施，预期为 2 → 3，不写死目标值），启动时版本不匹配即删库重建（沿用现有机制，不写迁移脚本）。重建后内部 `id` 重新分配，API 仍一律使用业务键字符串（C14）。

**R4 按分组聚合**
`getBreakdown` 的 group 维度，`key` 与 `name` 对自动分组统一取常量「默认」，其余保持 `group_path` / `display_name`；`GROUP BY` 改用与 `key` 相同的表达式，使全部自动分组合成一行。`COUNT(DISTINCT r.session_id)`、`tokenShare` / `creditShare` 的计算方式不变。维表缺失行仍兜底为「未知分组」（C13）。

**R5 虚拟业务键**
`buildWhere` 中 `group = '默认'` 映射为 `g.is_auto = 1`，其它取值仍映射为 `g.group_path = ?`。「默认」是虚拟键，不与任何 `group_path` 相等（`group_path` 恒为绝对路径），因此不会与手动分组的业务键冲突。维度筛选值仍从 JOIN 结果的 `DISTINCT` 取，自动分组不再单独枚举。

**R6 明细展示**
`getRequests` 返回的 `groupName` 对自动分组显示「默认」；`group` 字段仍为原始 `group_path` 业务键，不随展示名改变。面板不因该字段变化新增交互。

**R7 未知分组独立**
「未知分组」保持独立一行，不并入「默认」；其成因（`cwd` 为空、外部会话被清理后重解析）与现有 C7 / C13 处理不变。

**R8 一致性**
自动分组归并只改变分组的展示粒度，不改变任何请求行与聚合口径：在「全部时间 + 无筛选」下，按分组拆分各项指标之和仍等于总览合计（v1 R13 / AC3）；分组、对话、模型三种维度各自的求和仍一致。

**R9 只读与边界**
外部 `sessions.cwd` 仍以只读方式读取，不写 `workbuddy.db`；判定规则不引入网络调用或新的外部数据源。

## 边界情况

| 情况 | 处理 |
| --- | --- |
| Windows 路径含盘符、反斜杠、末尾反斜杠 | 统一切分后按 R1 判定，大小写不敏感 |
| `WorkBuddy` 目录名大小写不同（Windows） | 倒数第二段比较忽略大小写 |
| 路径末段形似日期但父目录不是 `WorkBuddy` | 判为手动分组，保留原展示名 |
| `WorkBuddy` 目录下用户手动创建的非日期目录 | 判为手动分组，保留原展示名 |
| `cwd` 为空串、NULL 或维表行缺失 | 归入「未知分组」，`is_auto = 0`，不并入「默认」 |
| 手动分组路径末段恰为「默认」 | 其业务键仍是完整路径、展示名仍是「默认」；下拉出现两个同名项时，手动分组展示回退为完整路径以区分，筛选互不影响 |
| 外部会话被清理 | 维表行与 `is_auto` 快照保留；文件重新解析且会话已不存在时按 C7 指向「未知分组」 |
| WorkBuddy 以后改变自动目录命名格式 | R1 判定失效，新目录被当作手动分组；属兼容性风险，需更新规则并重建索引，不静默猜测 |
| `group` 参数传入「默认」但库中没有自动分组 | 返回空结果，不报错 |
| 结构版本不匹配 | 按现有机制删库重建，重建后 `is_auto` 与聚合结果一致 |
| 删库重建后 | 内部 `id` 重新分配，API 参数与返回值仍只用业务键（C14） |

## 验收标准

- **AC1 判定规则**：单测覆盖 macOS POSIX 路径、Windows 盘符 / 反斜杠路径、末尾分隔符、大小写差异、日期末段但父目录不同的路径、`WorkBuddy` 目录下的非日期目录、空 `cwd`，结果与 R1 一致。
- **AC2 筛选下拉**：分组下拉不再出现任何 `YYYY-MM-DD-HH-MM-SS` 形态条目，只保留手动分组、「默认」与实际存在的「未知分组」。
- **AC3 拆分聚合**：按分组拆分列表中「默认」为一行的数值，等于全部自动分组请求按现有口径聚合之和；手动分组的行数与数值与改动前一致。
- **AC4 虚拟键筛选**：把分组筛选设为「默认」后，总览、趋势、三个拆分列表与请求明细只显示自动分组的请求；清除筛选后恢复全量。
- **AC5 明细展示**：自动分组请求的明细行分组列显示「默认」，`group` 业务键仍为原始路径。
- **AC6 一致性**：在「全部时间 + 无筛选」下，按分组、按对话、按模型三种拆分各自的指标求和仍等于总览合计（v1 AC3）。
- **AC7 未知分组**：`cwd` 为空的请求仍单独计入「未知分组」，不被并入「默认」。
- **AC8 结构重建**：`SCHEMA_VERSION` 递增后旧派生库自动删库重建；连续两次全量重建的分组聚合结果一致，与文件遍历顺序无关。
- **AC9 只读边界**：`workbuddy.db` 仍以只读打开，刷新前后外部文件大小与 mtime 不因本项目变化；不产生网络请求。
- **AC10 回归与检查**：v1.0.0 的 AC1–AC10 中除分组展示项外全部继续通过；`npm run typecheck`、`npm test`、`npm run build` 通过。
- **AC11 文档同步**：`product-brief.md`、`technical-architecture.md`、`data-model.md`、`integration.md` 中分组相关描述与本 Spec 一致；`integration.md` 明确记录 `group_id` / `group_title` / `project_id` 全为 NULL 的实测事实，以及路径判据与目录格式变化风险。

## 已确认决策

- 原始数据没有分组类型字段，只能靠路径形态判定；接受该启发式规则并把失效风险写入兼容性风险表。
- 「默认」作为可见的筛选项出现，替代 71 个日期条目；用户未要求隐藏全部自动分组，因此不提供排除开关。
- 「未知分组」保持独立，不并入「默认」。
- 保留每个原始 `group_path` 一行，只在维表加标记、在服务层聚合，不改写事实表外键。
- 虚拟业务键直接取「默认」，因 `group_path` 恒为绝对路径而不会冲突。
- 判定规则集中在解析层，兼容 macOS 与 Windows，不硬编码用户目录。
