# DeepSeek 官方价格对比与时间口径统一 Spec

## 背景与目标

面板已按日期、分组、对话、模型四维统计 token 与积分，但无法回答「这批用量如果直接调 DeepSeek 官方 API 要花多少钱，与 WorkBuddy 年费套餐摊销相比是贵还是便宜」。本次在 Token 趋势图上增加一条比率折线，用同一批请求的双侧等效费用做对比，不新增独立面板、指标卡或说明区。

实现前对全项目时间处理做了 review，发现「哪一天」和「显示几点」这两处依赖运行进程 / 浏览器的本地时区，而 DeepSeek 闲时判定需要固定时区口径。若只加折线而不统一时间口径，同一条历史数据在不同时区的机器上会落进不同日期、判出不同闲时，比率随之变化。因此本次一并修正：存储与流转保持绝对时间，业务日期归属与呈现固定到业务时区 UTC+8。

依据（只读试算，`deepseek-v4.1-flash`，2026-10-16 ~ 11-13，254 请求）：

- 输入 41,893,488，其中缓存命中 41,559,296（99.20%）；输出 325,203；合计 42,218,691。
- 消耗积分 1,567.29；套餐额度按「4000 + 100 × 当月自然日数」（10 月 7100、11 月 7000 积分），单价分别 0.007887 / 0.008 元/积分，摊销合计 12.52 元。
- DeepSeek 官方刊例价（人民币 / 百万 tokens，`deepseek-flash`，2026-11-14 抓取）：缓存命中输入 0.02/0.04 元、未命中输入 1/2 元、输出 4/8 元（空闲/高峰）。
- 按请求时间判定闲时的官方等效费用约 3.01 元，整体比率约 4.2×（10 月约 2.0×、11 月约 4.7×）。以上为当前派生库的试算值，用于说明量级，不是固定期望值。

目标：交付一条随四个筛选联动的比率折线；同时让所有时间派生不再依赖机器所处时区。

## 范围与非目标

**范围**

- 时间口径统一：新增单一业务时区常量；`date_key` 派生、日期键算术、前端「今天」、请求时间与刷新时间的格式化，全部改为不读机器时区。
- 预处理列 `is_deepseek_offpeak`：ETL 一次算定并落库，查询端不再做时间换算。
- 价格表、套餐参数、模型映射白名单、中国法定节假日表，作为常量与规则文档维护。
- 按天 × 闲时的轻量聚合，服务层产出比率序列；Token 趋势图增加第二 Y 轴与一条折线。
- 纯函数单测、跨时区回归、接口与交互验收断言、长期文档同步。

**非目标**

- 不做独立对比面板、指标卡、tooltip 里的口径说明、图例之外的任何说明文字；界面只多一条折线。
- 不做「全按缓存未命中」的第二套口径，界面不显示缓存命中提示或敏感性说明；口径与假设只写入长期文档。
- 不为非 DeepSeek 模型计算官方价格；筛选到非 DS 模型时折线整体隐藏，且不显示「不适用」提示。
- 不追溯官方历史价目表版本，历史数据统一套当前价目表并标注抓取日期；官方后续调价只改常量。
- 不配置 UI 设置面板，套餐参数与价格表写在代码常量里。
- 不接入官方计量接口、不统计积分余额 / 有效期、不导出、不改外部数据。

## 用户或系统行为

- Token tab 的按天趋势图：左侧 Y 轴仍是 token（按模型堆叠柱），右侧新增 Y 轴单位为「×」，绘制一条按天的比率折线，与堆叠柱共用日期轴与图例。
- 折线值 = WorkBuddy 套餐摊销费用 ÷ DeepSeek 官方等效费用。当前筛选范围无 DS 请求时折线隐藏，不显示任何替代文案。
- 四个筛选条件（时间、分组、对话、模型）对折线与堆叠柱同时生效；切换 tab、刷新数据不改变折线口径。
- 除这条折线外，现有指标卡、拆分列表、请求明细、tooltip 过滤 0 值、色表、排序、跨度上限等既有行为不变。

## 业务规则

**R1 绝对时间与业务时区**

- 所有时间字段（jsonl `timestamp`、`started_at` / `ended_at`、`synced_at`、`mtime_ms`、`parsed_at`、`last_refresh_at` / `last_full_scan_at`）继续以 UTC 毫秒时间戳存储与流转，不存本地时间字符串，这是绝对时间。
- 「哪一天」「显示几点」这类必须折算的场景，统一按固定业务时区 UTC+8（北京时间，无夏令时）折算，折算偏移量由 `src/shared/constants.ts` 单一常量给出，不读 `process.env.TZ`、不读浏览器时区、不依赖 ICU 时区数据库。
- 不采用纯 UTC 作为业务日期：会让北京时间晚间用量落到前一天，破坏「今天花了多少」的语义（AD-6 的原始理由）。
- `date_key` 仍由 `started_at` 派生（C5），但改为按 UTC+8 折算；对当前 GMT+8 环境产生的结果与改动前一致，换机器重扫不再改变历史归属。
- 日期键算术（`addDays` / `parseDateKey` / `isValidDateKey`）改用 UTC 纯日期算术，不再用本地零点构造 `Date`。`daySpan` 已是 UTC 解析，保持不变。
- API 的 `from` / `to` 仍是 `YYYY-MM-DD`，语义固定为 UTC+8 业务日期，不做时间戳转换。

**R2 闲时预处理列 `is_deepseek_offpeak`**

- 列名绑定规则来源：表示「按 DeepSeek 官方高峰 / 空闲规则，该请求是否落在空闲时段」。其他模型的闲时规则可能不同，不得复用本列；后续若扩展，另建各自的列或规则。
- 判定规则（官方中文页与英文页一致）：北京时间周一至周五、且非中国法定节假日、且 09:00–12:00 或 14:00–18:00 为高峰，其余为空闲；等价的 UTC 表述为周一至周五 01:00–04:00、06:00–10:00，不跨日。周末与法定节假日全天按空闲。
- 按请求的 `started_at` 判定，不按 usage 步骤时间；跨时段请求归入发起时刻。与 `date_key` 共用同一 UTC+8 折算，保证按天比率与时段同源。
- 所有请求都写入 0/1（避免 NULL），但只有 DS 价格计算消费该列；列说明中写明「非 DS 模型的值无业务含义」。
- 只固化时段事实，不固化费用：价格表仍是唯一真源，官方调价无需重扫日志。节假日表更新会改变历史判定，因此必须递增 `schema_version` 触发派生库重建；此约束写入文档。

**R3 价格表与模型映射**

- 价目表版本固定为 2026-11-14 抓取的 DeepSeek 中文定价页，人民币计价（与 672 元年费同币种，不引入汇率）。三档：缓存命中输入 0.02 / 0.04 元、缓存未命中输入 1 / 2 元、输出 4 / 8 元（空闲 / 高峰），单位「元 / 百万 tokens」。
- 模型映射用显式白名单：`deepseek-v4.1-flash` → 官方 `deepseek-flash`（DeepSeek-V4.1-Flash-1017）。不用 `deepseek*` 前缀推断。
- 官方分档与本地字段的对应：缓存命中输入 = `cache_read_tokens`，未命中输入 = `input_tokens − cache_read_tokens`，输出 = `output_tokens`；沿用 C3（`total = input + output`）与 C4（`cache_read ≤ input`），不新增 `cache_write` 字段。

**R4 套餐参数**

- 年费 672 元按 12 个月摊为 56 元/月；每月可获得额度 = `4000 + 100 × 该月自然日数`（签到按日计，取理论可获得的完整额度，不校验实际是否签满）。
- 单价按**请求所属自然月**确定：`单价(月) = 56 / (4000 + 100 × 该月天数)`。31 天月为 0.007887 元/积分、30 天月为 0.008 元/积分、平年 2 月为 0.008235 元/积分。月天数由 `date_key` 的年月用 UTC 纯日期算术求出，不依赖机器时区（R1）。
- 三个参数（年费、月基础积分、每日签到积分）集中一处并标注来源与确认日期；不得把某个固定单价写死。
- 该单价是「按总额度摊销」的平均价，不是边际成本；实际未用满额度时，摊销会把未用额度计入成本。此说明写入长期文档，界面不展示。

**R5 比率口径**

- 分子（WorkBuddy 摊销费用）= 当天 DS 请求 `Σ(credit × 单价(该请求所属月))`；无积分记录按 0 处理（沿用 C6，`has_credit` 不参与展示）。按天聚合时同一天必属同一自然月，服务层按 `date_key` 的年月取单价。
- 分母（官方等效费用）= 当天 DS 请求按 `is_deepseek_offpeak` 分档求和：`Σ(cache_read × 命中价 + (input − cache_read) × 未命中价 + output × 输出价) / 1e6`。
- 比率 = 分子 / 分母，无量纲；大于 1 表示 WorkBuddy 更贵。
- 服务层只返回有 DS 请求的日期；分母为 0 时该日 `ratio` 为 `null`。前端按连续日期轴对齐时，没有 DS 请求的日期补 `null`（折线断开），不画 0，避免出现假的 0×。
- 计算在服务层完成，前端只渲染，不自行求和或换算（AD-4）。

**R6 缓存语义**

- 本地 `cache_read_input_tokens` 视作 DeepSeek 官方「上下文缓存命中」，按命中价计费。这是对跨服务缓存等价性的假设，界面不提示，但必须在长期文档中记录该假设及其敏感性：若全按未命中计，官方等效费用会放大约一个数量级，比率反转到 1 以下（WorkBuddy 显得更便宜）。

**R7 节假日表**

- 中国法定节假日无算法可推，维护一张按 `YYYY-MM-DD` 的显式日期表，只录已公布的安排；未覆盖年份按「周一至周五」判定，并在文档中标注需年度更新。不编造未公布的放假安排。
- 现有数据区间（2026-10-16 ~ 11-13）不含法定节假日，当前比率不受该表影响。

## 边界情况

| 场景 | 期望行为 |
| --- | --- |
| 筛选到非 DS 模型 / 范围内无 DS 请求 | 折线整体隐藏，无提示；堆叠柱与其它视图不变 |
| 某天分母为 0（DS 请求全 0 token） | 该点 `null`，折线断开 |
| 请求正好落在 09:00 / 12:00 / 14:00 / 18:00 边界 | 按左闭右开判定：09:00–12:00、14:00–18:00 为高峰，12:00 与 18:00 计入空闲；写单测固化 |
| 周末、中国法定节假日、UTC 跨日 | 按 R2 / R1 判定，不依赖机器时区 |
| 跨零点的长请求 | 归入 `started_at` 所在业务日（C5 不变），闲时也按 `started_at` |
| 服务进程与浏览器处于不同时区 | `date_key`、「今天」、请求时间显示、闲时判定结果一致 |
| 官方后续调价 / 节假日表更新 | 改常量；节假日表更新需递增 `schema_version` 重建派生库；调价不需要 |
| 派生库版本不匹配 | 沿用现有机制删库重建，无迁移脚本、无外部数据写入 |
| 筛选区间跨月 | 各天用各自自然月的单价，不做区间平均或统一单价 |
| 某天分子为 0（有 token 但无积分记录） | 比率如实为 0；只有分母为 0 才置 `null` 断开折线 |
| 平 / 闰年 2 月、大小月 | 月天数按 UTC 日期算术求得，覆盖 28 / 29 / 30 / 31 天 |
| 按天比率显著偏离区间整体值 | 如实绘制，不做平滑、裁剪或阈值过滤 |

## 验收标准

- **AC1 时间无关性**：同一组绝对时间戳输入，在至少两种不同 `TZ` 环境下得到的 `date_key`、比率序列、`formatDateTime` / `formatRefreshTime` 结果一致；`toDateKey` / `todayKey` 单测覆盖 UTC、UTC+8、UTC-8 与跨零点。
- **AC2 闲时判定**：单测覆盖工作日高峰区间两端、12:00 / 18:00 边界、周末、法定节假日、UTC 跨日；断言与官方中英文页规则一致。
- **AC3 预处理落库**：刷新后 `requests` 每行都有 0/1；`date_key` 与 `is_deepseek_offpeak` 由同一 `started_at` 折算；`schema_version = 4`，旧库自动重建；查询端无 `new Date()` 式逐行换算。
- **AC4 比率数值**：用固定 fixture 断言分子、分母、比率与手算一致；分母为 0 的日期 `ratio` 为 `null`，范围内无 DS 请求时 `ratios` 为空数组、前端对齐后该点断开；全区间比率与逐请求手算结果一致。月度单价单测覆盖 28 / 29 / 30 / 31 天与跨月区间，断言大小月单价不同、跨月按各自月份取值，不写死单一单价。
- **AC5 折线**：Token 趋势图出现第二 Y 轴（单位 ×）与单条比率折线；日期轴与堆叠柱对齐；筛到非 DS 模型时折线不可见且无提示；界面不存在本次新增的说明文字、提示或指标卡。
- **AC6 回归**：五个既有 API 端点的 token / 积分聚合结果与明细结构不变；四个筛选、tab、排序、色表、tooltip 0 值过滤、跨度上限、默认近 3 天等既有验收项继续通过。
- **AC7 检查与文档**：`npm run typecheck`、`npm test`、`npm run build`、`npm run acceptance` 通过；`product-brief.md`（非目标）、`technical-architecture.md`（AD-6、接口表、分层）、`data-model.md`（列说明、C5、版本）、`devops.md`（验收覆盖）及新增的价格 / 节假日规则文档按实际实现同步，文档与代码无已知矛盾。

## 待确认问题

无。以下三项已在需求确认阶段定案：

1. 套餐额度为 `4000 + 100 × 当月自然日数`，按请求所属自然月确定单价（R4）。
2. 节假日表只录已公布安排，未覆盖年份按周一至周五判定（R7）。
3. 比率数据挂 `/api/timeseries` 扩展字段还是新增端点，留到 Plan 决定；本 Spec 只约定数据形状与口径。
