# Hover 模型聚焦与交互验收框架化 Spec

## 背景与目标

现有面板有两处「按模型分色」的展示，都缺少把单个模型从同组数据里挑出来的手段：

- **趋势图**（Token / 积分两个 tab 各一张）已配 `emphasis.focus: 'series'`：hover 到某个模型的堆叠块时，其它模型的系列进入 ECharts 默认 blur（不透明度约 0.1），几乎看不见；而 axis 触发的 tooltip 仍把当天所有模型按数值降序平铺，没有任何主次，看不出当前指向的是哪一个。
- **「按分组」拆分列表**（两个 tab 各一份）的数值条已按模型分段着色，但色段本身没有 hover 效果；整行 hover / 键盘 focus 浮出的明细提示虽然逐模型列出数额，各行也是等权呈现，且提示明确不接收指针事件。

现有交互验收由 `scripts/panel-acceptance.mjs`（约 1170 行）承担：它用 Node 内置 WebSocket 自研 CDP 客户端，要求手工启动带调试端口的 Chrome，靠固定时长的 `wait()` 与字符串拼接的 `Runtime.evaluate` 驱动页面，再用自定义 `check()` 逐项打印 PASS/FAIL；断言取数依赖真实 `~/.workbuddy` 数据，并以 `/api/timeseries` 的最早日期到当天构造「全量区间」，数据跨度超过 100 天时会在建立宽区间前直接报错。浏览器连接、等待、断言与报告全部自研，新增断言（例如本次 hover 聚焦需要的强度、极窄段命中与解除）成本持续上升。

目标：在这两处建立同一套「聚焦一个模型」的视觉语义——指针落在哪个模型上，tooltip 里就突出哪一行、减淡其余行；「按分组」色段也具备与图表一致的段级减淡；同时把图表现有过强的减淡调到可辨的程度。并把交互验收改用成熟、适合本项目技术栈的 e2e 测试框架，用固定样本数据替换真实本机数据，**按新框架的判定方式重写用例，完整保留既有 24 项验收覆盖且不放宽标准**。**不改变任何统计口径、聚合结果、数据契约与既有交互语义。**

## 用户或系统行为

1. **趋势图 hover 柱段**：指针落在某天某个模型的堆叠块上时，该模型成为聚焦模型；图表里其它模型的块减淡但不消失，tooltip 中该模型行保持完整可读、其余模型行减淡。指针离开柱段或离开图表后，所有块与所有行恢复常态。
2. **趋势图 tooltip 内容不变**：仍为 axis 触发，首行日期，随后是当天数值大于 0 的全部模型按数值降序，格式沿用 K / M / B 或积分两位小数；只是模型行带上聚焦状态。
3. **图表减淡强度调整**：非聚焦系列从现有「几乎看不见」提高到明显可辨，且与本交付在分组条、tooltip 行上使用的强度一致。
4. **分组条 hover 色段**：指针落在「按分组」某行的某个色段（含极窄段的最小命中区）上时，该段对应的模型成为聚焦模型；同一条内其它色段减淡，聚焦段保持常态；该行浮层中对应模型行保持常态、其余行减淡。宽度极小的段也要能被稳定命中。
5. **分组行内其它区域**：指针落在行内名称、数值、占比、条上未着色的空白区时，不聚焦任何模型，色段与浮层所有行均为常态；整行 hover / 键盘 focus 浮出提示的既有规则不变。
6. **键盘 focus**：整行 focus 只浮出提示，不产生模型级聚焦，浮层所有行常态。
7. **点击不变**：点击趋势图不做筛选、点击分组行仍写入分组筛选；聚焦是纯视觉状态，不改变任何筛选与数据。
8. **范围独立**：两张趋势图、两份「按分组」列表各自维护自己的聚焦状态，互不联动；同一时刻一处至多一个聚焦模型。
9. **一条命令跑验收**：执行 `npm run acceptance` 时，由 e2e 框架自动准备样本数据、启动服务与浏览器、执行用例、输出逐项结果并清理；不需要先手工启动 `npm run dev`，也不需要另开带 `--remote-debugging-port` 的 Chrome。
10. **固定样本数据**：用例运行在构造出的临时 `WORKBUDDY_HOME`（会话 jsonl + `workbuddy.db`）上，服务通过 `DATABASE_PATH` 把数据库建在同一临时目录并重建；同一份样本重复运行得到一致结果，真实 `~/.workbuddy` 数据不参与判定。
11. **框架驱动交互**：点击、hover、键盘 focus 与输入由框架的定位器和真实事件完成，等待由框架的自动等待机制承担；需要读取 ARIA 属性、DOM 几何尺寸、计算样式、canvas 数量与 tooltip 文本时，通过框架提供的页面求值能力读取**用户可见的渲染结果**，不调用图表内部的 option / formatter，也不自建 CDP 连接。
12. **失败可诊断**：任一断言失败时输出用例名、失败断言与定位信息（以及可选的截图 / 追踪），并以非零退出码结束；不得把环境未就绪记为通过。

## 业务规则

**R1 聚焦模型唯一且按业务键判定**
同一视图同一时刻至多一个聚焦模型，取值为指针所在色段对应的模型业务键：趋势图取该堆叠块 series 的 `id`（`TimeseriesRow.model`），分组条取 `BreakdownSegment.model`。判定与匹配一律用业务键，不用展示名，避免 C12 规范化与重名后缀影响（沿用 `model-color-binding` R1）。没有可判定的色段时聚焦模型为空。

**R2 强度统一**
聚焦项不透明度 1.0，非聚焦项 0.4。四处处处一致：趋势图的非聚焦系列（由 ECharts 默认 blur 约 0.1 调整为 0.4）、趋势图 tooltip 的非聚焦模型行、「按分组」条内的非聚焦色段、「按分组」浮层的非聚焦模型行。**0.4 是四处共用的唯一值，不因视图类型或模型色值深浅分别取值。**减淡作用于整块 / 整行（含色点与色标），不改变色值本身，也不改变视觉段宽与条长；不给聚焦项额外加描边、底色或加粗，高亮通过「其余减淡」形成。

**R3 趋势图聚焦**
沿用 `emphasis.focus: 'series'` 的作用范围：聚焦时同一模型在所有日期的块保持常态，其它模型在所有日期的块减淡；本交付只调整 blur 强度，不改 focus 语义，也不改为「只减淡同一天堆叠柱里的其它块」。tooltip 仍列出当天全部有值模型并按数值降序，其中聚焦模型对应的行为常态、其它行减淡；日期行与「无数据」不是模型行，不参与减淡，始终常态。指针位于空白类目、全 0 日、坐标轴、图例等非柱段位置时聚焦模型为空，tooltip（若出现）所有行常态。图例 hover 沿用 ECharts 既有的系列 emphasis 行为，不产生 tooltip 行聚焦。

**R4 分组条与浮层聚焦**
只对 `stackByModel` 的「按分组」行生效，且只在指针位于某个已渲染色段的命中区上时生效。聚焦时：同一条内其它色段减淡、该行浮层里同一业务键的模型行保持常态而其它行减淡。指针在同一行的不同色段间移动时，聚焦模型随之切换，不出现两行同时高亮或全部常态的中间态。
**允许为极窄段设置最小命中区**，使宽度很小的段也能稳定 hover。命中区只是交互区域，约束为：视觉段宽、段色、段序、各段宽度之和与条长一律不变；命中区限制在该数值条内，不侵占其它段的视觉区域，也不覆盖条上未着色的空白部分；同一指针位置仍只判定一个聚焦模型（R1），不因命中区扩大产生两义。具体阈值与实现方式在 Plan 阶段确定，不作为需求变量。浮层的内容、降序、0 值过滤、格式、`pointer-events: none`、定位翻转与键盘可达性全部沿用 `time-range-group-split-spec.md` R6。

**R5 状态解除与独立**
指针离开色段命中区 / 行 / 图表即解除聚焦；切换 tab、改变任一筛选、刷新数据、数据重新加载或组件重新渲染时清除聚焦，不把上一个模型残留到新的模型集合上。两个 tab 的趋势图与「按分组」列表各持一份状态，视图之间不联动、不广播；无聚焦时所有块、段、行一律 1.0。状态切换不引入新的动效或延迟，与现有 hover 反馈同步。

**R6 口径不变与分层**
全部为面板层展示层生成：不新增或修改 API、不改服务层聚合、不写数据库、不改颜色映射与筛选值。聚焦只读取已经渲染出来的模型业务键，不重新取数、不自行求和或换算。

**R7 兼容与回归**
0 值隐藏、8 行截断、段宽之和等于原单色条宽、段色与趋势图 / 色点逐值一致、tooltip 过滤与排序、点击筛选、明细折叠与排序、指标卡、请求明细、数值单位、刷新时间等既有行为不变。

**R8 框架化与覆盖等价**
交互验收由 Playwright 驱动。原脚本 24 项验收覆盖逐项保留、判定标准不放宽，逐项留下覆盖对照；**用例按框架重写**：断言用户可见的渲染结果（DOM 文本、计算样式、几何、tooltip 浮层、网络请求），不复刻旧脚本的白盒读法，不为迁就旧读法改动产品代码。格式化、刻度、0 值过滤、降序等纯逻辑由既有 Vitest 单测承担，e2e 不重复调用 option / formatter。不保留自研 CDP 客户端，不以手写 `wait()` 轮询和字符串拼接 `Runtime.evaluate` 作为主要交互方式。hover 聚焦 AC1–AC7 的新断言也写在同一套用例里，不新增第二套验收机制。

**R9 运行环境与样本数据**
`npm run acceptance` 单命令完成样本准备、服务与浏览器启停、用例执行与清理。样本为临时 `WORKBUDDY_HOME`，显式覆盖多模型、多分组、多日期、0 值、单模型日、极窄段与无数据日；跨度控制在 100 天以内，跨度超限的 400 分支另设用例验证。期望值由样本固定给出，不从 `/api` 现场反推。运行结束清理临时目录与数据库；用例只读页面与 `/api`，不写、不搬移真实 `~/.workbuddy` 文件。固定样本使「全量区间取最早日期到当天」的旧取数方式不再必要。

**R10 框架能力约束**
所选框架必须提供：测试运行器与用例组织、定位器与自动等待、断言与逐项结果报告、无头 Chromium、页面内 JS 求值（用于读 DOM 与计算样式，不用于调用图表内部 option / formatter）、无头环境下的焦点模拟或等价能力（既有键盘 focus 浮层断言依赖它）、失败时可诊断的截图或追踪；兼容 Node ≥ 24 与仓库 TypeScript 工具链，与 `npm run typecheck`、`npm test`、`npm run build` 共存且互不干扰。首次安装与浏览器二进制获取方式须写入 `devops.md`。这些是需求约束，具体版本与配置不在本 Spec 指定。

**R11 入口与文档同步**
`npm run acceptance` 指向新框架入口，`scripts/panel-acceptance.mjs` 从仓库移除；`devops.md` 的「交互验收」章节按新运行方式重写（不再要求手工启动调试 Chrome 与手工指定调试端口，补 `DATABASE_PATH`），`technical-architecture.md` 补记开发期测试依赖。长期文档与未归档交付文档统一「数据库」与「WorkBuddy 数据库」术语、去掉「派生」，并区分「表上的索引」；归档文档保留原样，已完成交付文档中的历史路径字面保留为当时事实。

## 边界情况

| 情况 | 处理 |
| --- | --- |
| 当天只有一个有值模型 / 某分组行只有一个有效段 | 没有非聚焦项，全部常态；不报错、不改变 tooltip 内容 |
| 图表全 0 日、空白类目、坐标轴或图例区域 | 聚焦模型为空，tooltip「无数据」与日期行不受影响，所有行常态 |
| tooltip 的日期行与「无数据」提示 | 不是模型行，始终常态，不随聚焦变化 |
| 分组行主指标为 0 或没有有效段 | 不渲染段、浮层显示「无数据」；无段可聚焦 |
| 模型筛选生效导致分组条只剩单段 | 同上，无减淡 |
| 段宽极窄 | 按 R4 提供最小命中区，使该段可稳定 hover；视觉段宽、相邻段宽度、段色与条长不变，同一指针位置不会命中两个模型 |
| 指针在行内名称、数值、占比或条上未着色的空白区 | 不聚焦任何模型（未被极窄段最小命中区覆盖时）；浮层仍按整行 hover 显示且所有行常态 |
| 指针从一个色段移到同一行的另一个色段 | 聚焦模型切换，至多一个模型高亮 |
| 键盘 focus 到分组行 | 浮出提示但无模型级聚焦，所有行常态；点击筛选行为不变 |
| 鼠标从色段移向浮层 | 浮层不接收指针事件，指针离开行后浮层按既有规则消失并解除聚焦 |
| 浮层因靠近视口边缘向下翻转 | 定位逻辑不变，聚焦状态不受影响 |
| 展示名重名（C12） | 按业务键匹配聚焦行，两个同名模型互不影响 |
| 被 0 值隐藏的模型 | 不在段、tooltip 与图表中出现，不参与聚焦 |
| 切换 tab / 改筛选 / 刷新 / 数据重载 | 聚焦清除；不残留到新的模型集合 |
| 两个 tab 同时存在（DOM 常驻、未激活隐藏） | 只有激活 tab 的视图响应 hover，隐藏视图不产生聚焦 |
| 样本里缺少某模型 / 单模型日 / 极窄段 | 样本显式构造这些场景，不依赖本机数据碰巧存在 |
| 样本跨度超过 100 天 | 主用例跨度控制在 100 天内，超限 400 分支单独验证 |
| 无头浏览器被判为未聚焦 | 用框架等价能力保证键盘 focus 浮层断言仍有效 |
| 隐藏 tab 的 ECharts 容器尺寸为 0 | 沿用既有 canvas 数与 `hidden` 断言，不靠固定等待 |
| 浏览器二进制缺失或首次安装未就绪 | 明确报错并指出安装步骤，不把用例记为通过 |
| 端口被占用 / 前后端构建版本错配 | 由框架统一管理服务启停与构建形态，失败时给出可定位信息 |
| 真实 `~/.workbuddy` 数据增长或格式变化 | 不影响验收结果；验收只认固定样本 |

## 验收标准

- **AC1 图表强度与作用范围**：分别在 Token / 积分图 hover 某模型的堆叠块，非聚焦系列的不透明度为 0.4、聚焦系列为 1.0；移出后全部恢复 1.0；作用范围仍是 `focus: 'series'`（同模型跨日期的块同步保持），两张图结果一致。减淡与恢复由页面可见的渲染状态断言；0.4 这个数值由 option 构建的纯函数单测锁定，e2e 不调用图表内部函数。
- **AC2 趋势图 tooltip**：hover 柱段时 tooltip 仍含日期行、当天全部 >0 模型且按数值降序、数值格式与转义不变；聚焦模型行 1.0、其余模型行 0.4；日期行与「无数据」始终 1.0；在空白类目 / 图例区域或无聚焦时所有行 1.0。
- **AC3 分组条**：两个 tab 的「按分组」行 hover 某色段时，该段 1.0、同条其它段 0.4，移出后全恢复；段数、段色、段宽之和与分段前单色条宽不变。构造极窄段用例时，该段可被 hover 并聚焦到对应模型；扩大命中区后视觉段宽、相邻段宽度与条长不变，且不出现同一指针位置命中两个模型。
- **AC4 分组浮层**：hover 段时浮层里对应业务键的模型行 1.0、其它行 0.4；hover 行内非段区域与键盘 focus 时所有行 1.0；浮层内容、降序、0 值过滤、格式、定位、`pointer-events: none` 与点击筛选行为不变。
- **AC5 强度唯一值**：四处减淡强度由同一常量给出，纯函数单测断言该常量为 0.4 且四处共用；e2e 断言四处可见的常态 / 减淡状态与移出恢复，不因视图或模型色值不同而出现其它强度。
- **AC6 独立与解除**：图表 hover 不改变「按分组」列表，反之亦然；同一视图至多一个聚焦模型；切 tab、改筛选、刷新与数据重载后无残留聚焦；两个 tab 行为一致。
- **AC7 回归**：统计口径与五个 API 端点响应结构不变；0 值隐藏、8 行截断、颜色按业务键、明细折叠与排序、指标卡、请求明细、数值单位、刷新时间等既有验收项继续通过；「按对话」「按模型」列表与单色条无变化；`usage-panel-polish`、`time-range-group-split`、`group-normalization`、`model-color-binding` 的既有 AC 继续通过。
- **AC8 检查与文档**：`npm run typecheck`、`npm test`、`npm run build` 通过；`npm run acceptance` 由新框架执行并通过；`devops.md`、`technical-architecture.md`、`data-model.md` 按实际实现同步，文档与代码无已知矛盾。
- **AC9 框架化**：交互验收由一个成熟 e2e 框架驱动；仓库中不再存在自研 CDP 客户端，也不存在以固定时长 `wait()` 与字符串拼接 `Runtime.evaluate` 为主体的用例；从用例与配置可核验框架提供的运行器、定位器与自动等待、断言与逐项报告。
- **AC10 覆盖等价**：原脚本 24 项验收覆盖逐项对照有记录且全部 PASS、退出码 0；对照的是覆盖项与判定标准，不是旧脚本的实现方式或数值结果；无删除覆盖、跳过断言或放宽标准；旧脚本从仓库移除，`npm run acceptance` 指向新入口。
- **AC11 一条命令与可复现**：`npm run acceptance` 单命令完成样本准备、服务与浏览器启停、用例执行与清理，无需手工启动 `npm run dev` 或调试 Chrome；连续运行两次逐项结果一致。
- **AC12 固定样本数据**：用例读写临时 `WORKBUDDY_HOME` 样本（多模型、多分组、多日期、0 值、单模型日、极窄段、无数据日），数据库由 `DATABASE_PATH` 指向同一临时目录，运行配置中不含真实 `~/.workbuddy` 路径；样本跨度不超过 100 天，超限 400 分支单独验证；运行结束临时目录与数据库被清理。
- **AC13 聚焦断言覆盖**：AC1–AC7 全部由框架用例以可见行为断言覆盖并逐条 PASS，含减淡强度、极窄段命中、tooltip 行聚焦、状态独立与解除、既有回归项；失败时输出用例名与失败断言。
- **AC14 与既有检查共存**：Vitest 单测（含 `tests/acceptance.test.ts`）不迁移、不降级，`npm test` 仍只跑单测；`npm run typecheck` 与 `npm run build` 不因引入框架而失败或降低校验范围。

## 已确认决策

- topic 为 `hover-model-focus`，三份交付文档共用该前缀。
- 聚焦只由色段（图表堆叠块 / 分组条色段）触发；两个 tooltip 保持纯展示、不接收指针事件，不增加「鼠标移到模型行上也能聚焦」的交互。
- 各自视图内联动：图表只影响自己的 tooltip，分组列表只影响本行色段与本行浮层；不做跨视图联动。
- 减淡强度**统一为 0.4 这一个值**：趋势图 blur、分组条非聚焦段、两个 tooltip 的非聚焦行都用 0.4，不因视图类型或模型色值深浅分别取值；聚焦项 1.0。
- 图表保留 `emphasis.focus: 'series'` 的整系列减淡，只把 ECharts 默认 blur（约 0.1）调到 0.4；不改成「只减淡同一天的其它堆叠块」，不改 focus 语义。
- 允许为极窄段设置最小命中区，规则与约束见 R4；具体阈值在 Plan 阶段确定。
- 聚焦项不需要额外视觉强化：不加描边、底色、加粗，靠「其余减淡」形成高亮。
- 交互验收框架化**并入 `hover-model-focus` 交付**，订正本 Spec，不新建交付文档；topic 与三份文档前缀不变。
- 既有 24 项验收覆盖**全量保留**：逐项迁移到框架用例，`scripts/panel-acceptance.mjs` 退役，`npm run acceptance` 改指向新入口，标准不放宽。
- 交互验收改用**固定样本数据**，不再依赖真实 `~/.workbuddy` 数据与「全量区间」取数方式。
- 原「不引入新依赖」的非目标修订为「不改产品运行时依赖」：e2e 框架作为开发期依赖引入。
- **框架选 Playwright**，服务形态为 `npm run build && npm start` 单端口，允许首次联网下载浏览器二进制；三项原待确认问题已由开发者确认。
- **断言按 Playwright 重写为可见行为断言**：保留 24 项覆盖清单且标准不放宽，但判定方式不照搬旧脚本；不读 ECharts 实例、不加产品代码测试钩子、不从 `/api` 现场反推期望值；格式化与图表内部状态的数值正确性由 Vitest 单测锁定。
- **数据库命名方案已确认并实施**：文件 `.data/database.db`、模块 `src/etl/database.ts`、函数 `openDatabase` / `closeDatabase`、测试 `tests/database.test.ts`、字段 `EtlConfig.databasePath`、可选环境变量 `DATABASE_PATH`（默认值 `.data/database.db`）；术语统一为「数据库」与「WorkBuddy 数据库」，归档文档不动。
- 固定样本复用 `tests/helpers/` 的构造器，期望值固定在样本里，样本规模以覆盖所需场景为下限。
