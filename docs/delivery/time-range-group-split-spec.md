# 时间快捷切换与分组条模型分段 Spec

## 背景与目标

v1.0.0 之后的面板在三处用起来别扭：

- 时间走下拉：常用区间要先点开下拉选预设、选「自定义」才出现两个日期框，切换要两步；下拉里的「本月 / 全部」少用，却又占着一层交互。
- 「按分组」数值条是单色 `--accent`：看不出这个分组的用量由哪些模型贡献；趋势图的 tooltip 已经能列出单模型数额，拆分列表却没有对应信息。
- `/api/timeseries` 除了按天按模型的聚合 `rows`，还顺带返回一份补齐空白日期的 `days` 坐标轴。这是旧「全部」预设不传日期时、由服务层替前端推断区间边界留下的历史做法；`days` 是展示形状而非统计口径，却让 API 承担了坐标轴职责，也让「轴」与「数据」两个数组可能错位。

目标：常用时间区间一步切换、与日期区间双向联动；「按分组」数值条按模型分段着色并给出明细提示；**把趋势图的日期坐标轴生成从服务层移回面板层**；**用 100 天跨度上限收敛长区间等特殊情况**。**不改变统计口径、不改变既有聚合结果、不改数据库结构与 `schema_version`。**

## 与既有交付的关系

本 Spec 覆盖 `usage-panel-polish-spec.md` 中筛选栏时间控件与拆分列表的呈现规则（其 R2 tab 状态、R3 固定行数、R5 单位、R7 0 值隐藏、R10 口径不变与分层保持有效），并扩展 R7 的作用范围到分组条的色段与提示。模型颜色沿用 `model-color-binding` 已固定的业务键色表，分组键沿用 `group-normalization` 的「默认」归一化口径。本 Spec 还会**收缩** `/api/timeseries` 的响应结构（去掉 `days`），这是 v1 以来该端点第一次删字段；`technical-architecture.md` 的接口表与分层原则需同步。归档的 `docs/delivery/v1.0.0/` 与上述已完成的交付文档不改写。

长期文档需按本 Spec 更新：`product-brief.md`（范围段时间入口、跨度上限与「图表堆叠只按模型着色」的措辞）、`technical-architecture.md`（筛选栏描述、面板层分层原则与补轴职责、接口表中 `/api/timeseries` 与 `/api/breakdown` 的返回值及跨度校验的 400 分支）、`docs/model-colors.md`（色标覆盖视图增加分组数值条）、`devops.md`（交互验收脚本覆盖范围与跨度上限）。`data-model.md` 与 `integration.md` 不涉及：不改表、不改解析与外部数据。

## 范围与非目标

**范围**

- 时间区改为四个快捷按钮「今天 / 3 天 / 7 天 / 30 天」+「更多」展开的起止日期框，按钮与日期双向联动；移除「本月 / 全部」预设。首屏默认与「重置」都落在「近 3 天」。日期框默认收起，让筛选栏只占一行；展开后右侧三个维度下拉与「重置」仍靠上对齐。
- **时间区间跨度上限 100 天（含首尾）：超限由 API 返回 400，前端在筛选栏显示错误并保持上一次有效区间；不为超限区间提供降级展示。**
- **`/api/timeseries` 只返回按天按模型拆分的 `rows`，不再返回 `days`；连续日期轴由面板层用共享 `enumerateDays()` 生成。**
- 服务层为 group 维度拆分结果附加**按模型分段**的交叉聚合数据。
- Token 与积分两个 tab 的「按分组」列表：数值条改按模型分段着色，hover / 键盘 focus 浮出单模型明细。
- 类型契约、纯函数单测、交互验收断言、长期文档同步。

**非目标**

- 不改统计口径（C2 取最大值归并、C6 积分挂接、v1 R8 积分归属、R13 维度一致性），不改数据库表结构、不新增表、不改刷新流程；**除 `/api/timeseries` 去掉 `days` 与所有端点新增「跨度超限 400」分支外，其余响应语义不变**。
- 不新增筛选维度，不改分组 / 对话 / 模型下拉、tab 状态、明细折叠与排序、数值单位、0 值隐藏规则本身。
- 不做单日快捷项、不做日历组件（沿用原生 `input[type="date"]`）、不做「清空区间 = 不限时间」语义、不提供自定义区间命名或保存。
- **不提供超过 100 天的区间，也不为超限区间做按周 / 月聚合、下钻或分页**；保持「时间粒度只有天」的产品约定。
- 不改「按对话」「按模型」两个拆分列表、请求明细表与指标卡；趋势图只调整日期轴的来源，堆叠着色与 tooltip 口径不变。
- 不改 `enumerateDays()` 本身及其 3700 循环上限（跨度上限后不可达）。
- 不引入新依赖、不引入深浅主题、不改 `~/.workbuddy` 下任何原始数据，不新增外部数据源。

## 用户或系统行为

1. **时间区形态**：筛选栏时间字段为四个快捷按钮 +「更多 / 收起」按钮 +「重置」；点「更多」才展开「起始日期 至 结束日期」两个输入框，收起时筛选栏只占一行。页面上不存在「本月 / 全部 / 自定义」入口。首屏默认选中「3 天」。当前生效区间若恰好等于某个预设区间，则该按钮高亮；否则四个按钮都不高亮，表示自定义区间。
2. **点快捷按钮**：立即把 `from / to` 设为对应区间，日期框同步显示该区间，所有视图按新区间刷新；已选的分组 / 对话 / 模型保留。
3. **手动改日期**：改动即时生效，日期框保持用户输入值，按钮高亮按当前区间反向匹配重算；不需要「应用」按钮。
4. **非法区间**：起始晚于结束时显示错误提示「起始日期不能晚于结束日期」，不写入筛选，视图保持上一次有效区间。
5. **状态保持**：切换 tab、展开明细、改排序、刷新数据都不重置时间状态；「重置」回到「近 3 天」并清空其它三个筛选（沿用现有重置语义，只把默认区间由今天改为近 3 天）。
6. **分组条分段**：两个 tab 的「按分组」数值条按模型切成多个色段，颜色与趋势图系列、模型色点一致；条的整体长度仍表示该行占全部行的比例，各段长度按该模型在该分组的数额分摊。
7. **明细提示**：hover 或键盘 focus 某一行时浮出提示，顶部为分组名与该行合计，下面逐行「色点 模型名：数额」，按数额降序；Token tab 用 K / M / B，积分 tab 用两位小数，与列表数值一致。
8. **点击不变**：点击某一行仍是把该分组写入筛选；提示浮层不承载点击、不改变行高、不遮挡原有交互。
9. **其余视图**：「按对话」「按模型」保持单色数值条与现有行为，不出现分段与明细提示。
10. **趋势图日期轴**：API 只返回有数据的按天按模型行；面板按当前 `from / to` 补齐中间没有数据的日期（补 0），x 轴区间与筛选条件一致。
11. **跨度上限**：手动选择的起止区间跨度超过 100 天时，筛选栏显示错误「时间跨度不能超过 100 天」，所有视图保持上一次有效区间；直接调用 API 携带超长区间返回 400 与同一错误文案。跨度不超过 100 天时行为与现在完全一致。

## 业务规则

**R1 时间状态唯一与预设口径**
当前生效的 `from / to` 是时间状态的唯一来源，日期框取值与按钮高亮都由它计算，不再有与它并列的预设 / 自定义状态。四个预设区间由页面加载时取一次的 `today` 计算：今天 = `[today, today]`；3 天 = `[today-2, today]`（含今天共 3 天）；7 天 = `[today-6, today]`（含今天共 7 天）；30 天 = `[today-29, today]`（含今天共 30 天）。按钮高亮 = 当前区间与四个预设区间逐一比对的结果，至多一个按钮高亮。首屏与「重置」的初始区间都是 3 天。跨零点后不自动重算 `today`，沿用现有 `todayKey()` 一次取值的行为。

**R2 立即生效与输入边界**
日期改动即时写入筛选条件；`from > to` 或跨度超限时都不写入并显示错误提示；日期框不允许空值，用户清空输入时值回弹到当前生效值、筛选不变。不提供「不限时间」入口，也不把空值解释为无上 / 下界。

**R3 切换保留**
切换时间只替换 `from / to`，保留 `group / session / model`（沿用 `applyPresetRange` 的效果）；tab 切换、明细折叠与排序、刷新都不重置时间。重置回到「近 3 天」区间并清空三个维度筛选。

**R4 交叉聚合数据**
服务层在 group 维度拆分结果中附加按模型的分段数据（每段含模型业务键、模型展示名、合计 token、积分），与同一查询的汇总行同源、同筛选、同分组键；分组键沿用 `GROUP_KEY`（自动目录归并为「默认」），模型键与展示名沿用现有 `COALESCE(m.model, '未知模型')` 与 C12 展示名规则。原有字段与语义不变，新增内容为向后兼容的附加字段；`tokenShare` / `creditShare` 仍按全量分组合计计算。具体参数与字段形态在 Plan 阶段确定。

**R5 分段渲染**
只渲染主指标大于 0 且属于当前 tab 可见模型集合的段（R7 0 值隐藏的判定集合仍取「不含模型筛选」的 `modelOptions`，与分段数据互不混用）。段色 = `modelColor(段模型业务键)`，与趋势图、色点逐值一致。段宽按该段数值占该行数值的比例分摊到原有条宽上，因此各段宽度之和等于原单色条宽度；行值为 0 或没有有效段时不渲染色段。相邻段之间用细白色分隔保证同系列相近色可辨，不改变色值。

**R6 明细提示**
hover 与键盘 focus 都触发；内容为分组名、该行主指标合计，以及各有效段的「色点 + 模型展示名 + 数额」按数额降序列表；只列主指标大于 0 的段，无有效段时显示「无数据」。提示沿用趋势图 tooltip 的过滤与排序语义，数值格式沿用 `formatTokens` / `formatCredit`；提示为不接收指针事件的浮层，不改变行高、不影响点击筛选，且需考虑键盘可达与视口内定位。

**R7 口径不变与分层**
分段数值由服务层聚合，面板只做展示层生成：按当前主指标过滤段、按比例计算段宽、格式化、查模型色表。面板不自行求和或换算聚合值，颜色不进入 API、不写入数据库；趋势图的连续日期轴同属展示层生成。

**R8 兼容**
三个拆分列表仍最多 8 行、固定行高、无内部滚动；「N 项」与占比按全量结果计算；点击行仍是筛选；模型筛选生效时分段数据随之收敛；两个 tab 共用同一份筛选与状态。

**R9 日期轴职责归位**
`TimeseriesResponse` 去掉 `days`，`GET /api/timeseries` 只返回 `rows`。服务层不再推断区间边界、不再生成坐标轴；面板层负责按筛选条件生成连续日期轴。统计口径、堆叠着色、tooltip 与其它端点不变。这是本交付唯一的响应字段删减。

**R10 连续日期轴**
面板用 `src/shared/dates.ts` 的 `enumerateDays(from, to)` 生成含首尾的连续日期并逐天补 0，行为与现有服务层生成的结果一致；跨度上限后最多产出 100 项。`from > to` 或 `rows` 为空时不生成轴（沿用错误提示 / 空态）。由于 100 远小于 `enumerateDays` 的 3700 循环上限，该上限不会被触及，**`enumerateDays` 本身与其 guard 不改**；本交付只在共享层新增跨度计算纯函数。

**R11 跨度校验（单一规则、两端执行）**
跨度按**含首尾天数**计算，上限 `MAX_RANGE_DAYS = 100`（即 `to - from ≤ 99` 天差）。规则由 `src/shared/` 的常量与纯函数单一实现，前端与 API 共用：

- 前端：日期改动时即时校验，超限时在筛选栏显示「时间跨度不能超过 100 天」、不写入 `filters`、不发起无效请求、所有视图保持上一次有效区间；四个快捷预设与重置产生的区间天然合法，且会清除已有错误。
- API：四个读取筛选的端点（summary / timeseries / breakdown / requests）共用的筛选解析在 `from` 与 `to` 都存在时校验，超限返回 400 与同一错误文案，作为契约兜底；缺失任一日期时不校验跨度（放行），保留 API 不带日期取全量的能力。
- 两端文案一致，不因入口不同出现两种解释。

## 边界情况

| 情况 | 处理 |
| --- | --- |
| 首次打开页面或点击「重置」 | 区间为 `[today-2, today]`，「3 天」按钮高亮，三个维度筛选为空 |
| 手动把日期改成恰好等于某个预设区间 | 反向匹配后对应按钮自动高亮 |
| 手动改成任意其它合法区间 | 四个按钮都不高亮，筛选按该区间立即生效 |
| 跨度恰好 100 天 | 正常生效，趋势图 100 个按天类目 |
| 跨度 101 天 | 筛选栏显示「时间跨度不能超过 100 天」，视图与查询串保持上一次有效状态；不发有效请求 |
| 选了 101 天后改回合法区间 | 错误提示清除，视图按新区间刷新 |
| 直接调用 API 携带跨度 > 100 的 `from / to` | 返回 400，错误文案与前端一致；四个筛选端点一致 |
| 只传 `from` / 只传 `to` / 都不传 | 不校验跨度，API 正常返回；前端日期框不会出现该状态 |
| 起始晚于结束 | 显示现有错误提示，不写入筛选，视图保持上一次有效区间与上一次有效轴 |
| 清空某个日期框 | 值回弹到当前生效值，筛选不变；不提供「不限时间」 |
| 跨零点后仍开着页面 | 预设区间按页面加载时的 `today` 计算，不自动重算 |
| `/api/timeseries` 响应中没有 `days` | 面板自行生成轴；其余端点不读取该字段 |
| 0 值隐藏后 `rows` 变少 | 日期轴不受隐藏影响（用原始 rows 与 `from / to` 计算） |
| 选中某个模型后 | 分段数据只剩该模型，条呈单色；按钮高亮不受影响 |
| 分组在当前 tab 主指标为 0 | 不渲染段、不显示明细，条为空（与现有占比 0 一致） |
| 某模型在当前 tab 主指标为 0 | 段与提示都不显示；该模型贡献为 0，不改变条总长 |
| 「默认」虚拟分组 / 未知分组 | 交叉聚合按同一 `GROUP_KEY` 归并，段随该行走 |
| 分组被 8 行截断 | 只有可见行渲染段与提示；全量占比与「N 项」不变 |
| 分组数据加载中或请求失败 | 沿用现有骨架 / 错误态，不显示半截色条 |
| 分段中出现重名模型（C12） | 按业务键分段，展示名用服务层下发的模型展示名 |
| 相邻段颜色相近 | 细白色分隔保证可辨，不改变色值 |
| 键盘 focus 到某一行 | 与 hover 相同显示明细，原点击筛选行为不变 |
| 提示浮层靠近面板边缘 | 定位限制在可视区域内，不溢出 |

## 验收标准

- **AC1 时间控件**：筛选栏有四个快捷按钮「今天 / 3 天 / 7 天 / 30 天」与「更多」按钮，无「本月 / 全部 / 自定义」入口；起止框由「更多」展开、默认收起，收起态筛选栏只占一行，展开态右侧下拉靠上对齐；首屏默认「3 天」高亮且日期框为 `[today-2, today]`。
- **AC2 双向联动**：点四个按钮，日期框分别回填 `[today,today]` / `[today-2,today]` / `[today-6,today]` / `[today-29,today]` 且只高亮对应按钮，发出的 `/api/summary` 查询串与区间一致；手动改日期立即生效且高亮按反向匹配更新（匹配上高亮、否则全灭），无需「应用」按钮。
- **AC3 保留与重置**：切换时间不清空分组 / 对话 / 模型；切 tab、展开明细、改排序、刷新都不改时间；起始晚于结束显示错误且视图不变；清空日期框回弹；重置回到「近 3 天」且清空其它筛选。
- **AC4 分段着色**：两个 tab 的「按分组」条按模型分段，段色与趋势图系列 / 模型色点逐值一致；各段宽度之和等于原单色条宽度；「按对话」「按模型」保持单色。
- **AC5 明细提示**：hover 与键盘 focus 都浮出分组名 + 合计 + 逐模型数额（降序、隐藏 0 值），数值格式与列表一致；点击行仍写入分组筛选；提示不改变行高、不遮挡点击。
- **AC6 口径与契约回归**：`/api/timeseries` 响应不含 `days`、只返回按天按模型的 `rows`；四个筛选端点新增「跨度超限 400」分支且其余响应语义不变；group 维度新增分段为附加字段；分组 / 对话 / 模型 / 请求明细合计与总览一致；0 值隐藏、8 行截断、tab 状态、数值单位、刷新行为不变；v1.0.0 与既有交付的验收项继续通过（涉及 `days` 的旧断言按新契约改写）。
- **AC7 检查与文档**：`npm run typecheck`、`npm test`、`npm run build` 通过；`npm run acceptance` 补时间联动、日期轴归位、跨度上限与分段提示断言后通过；长期文档按实际实现同步且与代码无已知矛盾。
- **AC8 日期轴归位**：面板按 `from / to` 生成连续轴，选近 7 天时即使中间无数据也画满 7 格；`/api/timeseries` 响应体不含 `days`；趋势图不再依赖服务层下发的轴。
- **AC9 跨度上限**：选 100 天区间正常生效、趋势图 100 个类目；改成 101 天时筛选栏显示「时间跨度不能超过 100 天」、视图与查询串保持上一次有效状态、不产生成功的 `/api/summary` 请求；直接请求 `/api/summary?from=…&to=…`（跨度 > 100）返回 400 且错误文案一致；不传日期参数的 API 请求仍可返回全量；改回合法区间后错误清除、视图刷新。

## 已确认决策

- **按钮确认为四个「今天 / 3 天 / 7 天 / 30 天」，保留「今天」**。
- 时间控件采用「四个快捷按钮 +「更多」展开的起止日期框」，去掉「本月 / 全部」；起止框默认收起、展开后右侧下拉靠上对齐；不引入「清空区间 = 不限时间」这类需要额外解释的语义。
- **默认与重置都落在「近 3 天」**（`[today-2, today]`）。
- 「特定日期」只要起止区间，不做单日快捷项与日历组件。
- 按钮与日期双向联动，手动改日期即时生效，高亮按当前区间反向匹配（匹配上高亮、否则四个都不高亮）。
- **跨度上限 100 天（含首尾），超限由 API 返回 400、前端在筛选栏显示错误；不做降级展示、不改 `enumerateDays` 的 3700 guard、不引入按周 / 月聚合。**
- **一起做：`/api/timeseries` 去掉 `days`，日期轴由面板层生成**；跨度上限后 3700 guard 不可达，无需修改共享函数。
- 分段着色只作用于「按分组」列表；「按对话」「按模型」不动。
- 条长仍表示该行占全部行的比例，各色段按模型数额分摊。
- 提示为整行浮出明细（分组名 + 合计 + 逐模型），对齐趋势图 tooltip 的过滤与排序语义。
- 颜色复用 `modelColor()`；0 值隐藏按当前 tab 主指标作用于色段与提示。
- 交叉聚合由服务层提供，不改数据库结构与 `schema_version`，不改统计口径。
