# 面板展示与验收细节修正

## 背景

`usage-panel-polish` 交付复核（2026-11-12）逐条核对了实现与文档，功能与验收标准整体达成；同时发现若干展示层、可访问性与测试记录层面的细节问题。这些问题不改变统计口径，也不影响已通过的验收标准，但会让面板在特定操作下变差、或让以后维护与回归变难，故集中记录待处理。

## 问题

1. **模型下拉在选中后塌缩**：`src/web/App.tsx` 用含模型筛选的 `modelRows` 计算 `visibleModelKeys`，再用它过滤去掉模型筛选的 `modelOptions`。选中某个模型后按模型拆分只剩 1 行，下拉只剩该模型与「全部模型」，无法直接切换到其他模型；带分组 / 对话筛选时还会用局部口径删掉全局有值的模型。
2. **`aria-controls` 指向未挂载面板**：`ModuleTabs` 给两个 tab 都写了 `aria-controls`，但未激活面板不挂载，非激活 tab 的引用悬空。
3. **面板 id 未与函数打通**：`modulePanelId()` 只用于 `aria-controls`，面板 id 仍由 `App` 手写字面量，两处可能漂移。
4. **趋势图配色随 tab 漂移**：`TrendChart` 按当前可见模型排序后取调色板，两个 tab 的可见集合不同，同一模型可能换颜色。
5. **0 值判定与文档表述有微差**：`visibleModelKeys` 用 `metric > 0`，Spec R7 写的是过滤 `=== 0`；负值会被当作 0 值隐藏，且无单测覆盖。
6. **两处测试名实不符**：`tests/acceptance.test.ts` 的 `describe('AC11 界面结构')` 只断言服务层聚合；`tests/api.test.ts` 中「与筛选无关」的用例只断言类型，未比对带筛选与不带筛选的值。
7. **K / M / B 进位边界**：`formatTokens(999_999)` 输出 `1000.0K`，与「数值易读」目标相悖，已被单测固化。
8. **交互验收脚本未入库**：AC1–AC9 的 DOM 断言依赖一次性 CDP 脚本，复核后无法直接复跑。

## 预期价值

- 恢复下拉的完整切换能力，避免用户选完模型后只能靠「重置」退出。
- 补齐 tab 与面板的可访问性关联，减少读屏与键盘用户的困惑。
- 让模型颜色在 tab 间稳定，便于跨模块对照同一模型。
- 让 0 值判定与文档一致并有单测，消除负值语义的模糊。
- 让验收结论可复跑，降低后续回归成本。

## 已知约束

- 下拉口径需要先确认判定集合：按当前筛选（含模型）判断会让下拉塌缩；按去掉模型筛选的集合判断才能保证选中后仍可切换。改动需同步更新 Spec R7 与 AC7。
- `aria-controls` 与面板 id 属展示层，不影响统计口径；若改为始终渲染面板容器并隐藏，需要重新评估 ECharts 在零尺寸容器中的初始化路径。
- 配色稳定需要把颜色绑定到模型标识而非可见序号，且不能与既有 12 色板冲突。
- 不引入 DOM 测试框架；可复算逻辑仍走单测，交互验收脚本入库前需确认存放位置与运行前提（Node 24 + 本机 Chrome）。
- `formatTokens` 的进位规则属 Spec R5 阈值，调整需先确认是否接受 `1000.0K` 之外的口径。
